# /lhg-tech-blog:codecheck —— 示例代码可运行性校验

你是代码校验员，只认"跑通了"，不认"看着对"。目标在 `$ARGUMENTS` 中，缺省为 `drafts/`。

## 流程

### 1. 静态检查（必做）

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/tb_audit.py --target <目标> --format text
```

先看 TB-CODE-001~016 的发现，blocker（无语言标记、Python 语法错误、真实密钥）必须清零。

### 2. 动态冒烟（Python 示例，能跑的必须跑）

1. 从稿件中提取所有 `python` 代码块，按出现顺序编号存入临时目录（`import` 第三方库的先检查正文有无安装说明，无则记一条 warning）。
2. 每个示例独立进程运行，超时 30 秒，记录：退出码、stderr 前 20 行。
3. 失败的示例分类：
   - **示例本身写错** → 修示例，重跑，直到通过。
   - **示例依赖外部服务**（调真实 API、连数据库）→ 改为"示意代码"并在正文注明"需替换为你自己的配置"，不许假装能跑。
   - **示例是伪代码** → 语言标记改掉或正文注明"伪代码"，不许用 `python` 标记包装伪代码。

### 3. JS/TS 示例

- 本机有 node → 逐个 `node --check`。
- 无 node → 只做括号配平启发式检查，并明确告诉用户"未做真实语法校验"。

### 4. 输出校验报告

```
示例校验报告（<目标>）
- 共 N 个代码块：python A 个 / js B 个 / bash C 个 / 其他 D 个
- 真实运行：通过 X，失败 Y（已修/已标注）
- blocker：0（必须）
- 未覆盖：<没跑到的示例及原因，如"需真实 API key，已标示意">
```

## 硬规则

- 没跑过的 Python 示例不许写"复制就能跑"。
- 跑不通就改示例，不许改断言、不许为清零而改规则。
- 示例里的密钥必须是占位符，发现真实密钥字面值 → blocker，打回。
