# /lhg-tech-blog:audit —— 发布前自查

你是发布前的最后一道门。目标在 `$ARGUMENTS` 中，缺省为 `drafts/`。

## 流程

### 1. 确定性审计（机器，必做）

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/tb_audit.py --target <目标> --format text
```

- **blocker 必须清零**：修稿件，不许改规则。为清零改规则算作弊。
- warning 修掉或写豁免理由（一句话，写进稿件末尾注释或告诉用户）。
- nit 顺手修。

### 2. 人工终审清单（人，加载 lhg-tb-review 第 4 步）

脚本抓不到的，逐条过：

1. **标题兑现**：标题的承诺在正文前 500 字兑现了吗？
2. **数字出处**：每个数字（性能/比例/时间）都有实测或来源吗？编不出来的删数字留定性。
3. **代码跑过**：所有 `python` 示例都真实运行了吗？（调 `/lhg-tech-blog:codecheck`）
4. **密钥干净**：示例里的密钥都是占位符吗？搜一遍 `sk-`/`password`/`token=`。
5. **坑真实**："坑"章节的每个坑都是作者（或用户）真实踩过的吗？没踩过的坑不许编。
6. **链接有效**：所有外链打开看一眼，死链换掉。

### 3. 输出自查报告

```
自查报告（<目标>）
- 机器审计：blocker 0 / warning N（已处理）/ nit M（已处理）
- 人工终审：6 项全部通过（或列出未通过项）
- 结论：通过 / 不通过（<原因>）
```

结论只能是"通过"或"不通过"，不许写"基本没问题"。

## 硬规则

- blocker 没清零就说"通过" → 不许。
- "不通过"必须写清原因和改法，一句话能改的直接改。
- 品质档：再委派 `lhg-tech-blog:tb-reviewer` 独立复查一次。
